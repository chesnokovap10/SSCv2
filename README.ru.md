# SSCv2

[English](README.md) · **Русский**

Программа в трее для Windows: передаёт звук на Samsung Galaxy Buds через **встроенный
Bluetooth MediaTek MT79xx** (MT7921/MT7922/MT7902) в обход стека Windows — кодеками **AAC**,
**SSC** (Samsung Scalable Codec, 24 бит / 48 кГц) и **SSC UHQ** (96 кГц) — и при этом
сохраняет работу **BLE-мыши**. Главного окна нет: значок и меню по правому клику.

Версия: `0.1 #<хеш коммита>` (например, `0.1 #67cd8794`), видна в меню и в «Инфо».

## Установка и обновление

Запустите `ssc.exe` из любой папки. При первом запуске программа (с запросом UAC) копирует
себя в `C:\Program Files\SSCv2`, кладёт ярлык **SSCv2** на рабочий стол и запускается оттуда.
Если программа уже установлена, а запущен другой файл — установленная копия **обновляется**:
работающий трей возвращает Bluetooth Windows, закрывается, файл заменяется, новый трей
продолжает с тем же кодеком. В список «Приложения и возможности» программа не записывается.

`SSCV2_PORTABLE=1` — запуск без установки (для отладки).

**Удаление:** «Настройки → Удалить программу…». Bluetooth возвращается Windows, удаляются
служба, виртуальные наушники, `Program Files\SSCv2`, `%ProgramData%\SSCv2`, настройки, ключи
сопряжения, журналы и ярлык. Файл, из которого программа была установлена, остаётся.

## Меню

| Пункт | Что делает |
|---|---|
| **Кодек ▸** Выкл / AAC / SSC / SSC UHQ | «Выкл» — адаптер у драйвера Windows (BTHUSB), наушники и мышь работают как обычно. Остальное — адаптер в WinUSB, прошивка MT79xx, BTstack, наушники на выбранном кодеке, мост мыши. |
| **Битрейт ▸** | Список для текущего кодека; «Авто» — см. ниже. |
| Сопрячь устройство ▸ | Импорт ключей из Windows, поиск рядом (когда кодек включён), выбор наушников и мыши. |
| Инфо об устройствах… | Адаптер, чип/прошивка, наушники (кодек, битрейт, громкость), мышь, служба. Тот же текст — по левому клику на значке. |
| **Настройки ▸** Язык | Русский / English (по умолчанию — язык Windows). |
| Настройки ▸ Макс. MTU для Samsung Galaxy Buds2 Pro | Пакеты до 1017 байт вместо объявленных наушниками 679: AAC 256 кбит/с целыми кадрами. Samsung Galaxy Buds2 Pro играют чисто, другие наушники могут такие пакеты отбрасывать — поэтому опция. |
| Настройки ▸ Все битрейты | Показывать и битрейты выше максимального, проверенного на этих наушниках (см. «Профили наушников»). |
| Настройки ▸ Отладочный журнал | Подробный общий журнал всех процессов (`debug.log`, см. ниже). |
| Настройки ▸ Открыть папку журналов | `%LOCALAPPDATA%\SSCv2\logs`. |
| Настройки ▸ Запустить / Удалить службу | Служба-помощник (LocalSystem): с ней переключения и импорт ключей идут без запросов UAC. |
| Настройки ▸ Удалить программу… | Полное удаление (см. выше). |

Цвет значка: серый — выкл, жёлтый — переключение/подключение, синий — ждём наушники,
зелёный — идёт поток, красный — ошибка.

### Кодеки и битрейты

| Кодек | Битрейты, кбит/с | «Авто» |
|---|---|---|
| AAC | 128, 160, 192, 224, 256 | сколько вмещает пакет наушников: `(MTU − 12) × 8 × частота / 1024`, не больше 256 (Samsung Galaxy Buds2 Pro: 250 при 48 кГц; с «Макс. MTU» — 256) |
| SSC | 88, 96, 128, 192, 229, 256, 328 | рабочий максимум наушников, если он известен (Samsung Galaxy Buds2 Pro: 229), иначе наибольший, что вмещает пакет: 256, с «Макс. MTU» — 328 (128, если наушники объявили ограничение) |
| SSC UHQ | 152, 250, 291, 308, 442, 584, 886 | наибольший, что вмещает пакет (584; с «Макс. MTU» — 886) |

* SSC — наш `libssc`, бит-точная копия энкодера из прошивки телефона. Нужен вывод Windows на
  48000 Гц. Телефон на 48 кГц шлёт не больше 192; 256 и 328 — «широкие» режимы энкодера.

### Профили наушников

В `internal/engine/profiles.go` для каждой модели записан наибольший битрейт, проверенный на
слух. Модель узнаётся по Bluetooth Device ID (VID/PID, которые Windows записала при сопряжении:
`BTHPORT\Parameters\Devices\<mac>` `VID`/`PID`); по имени Bluetooth — только если Windows
устройство не знает. Пока проверены только **Samsung Galaxy Buds2 Pro** (SM-R510, Samsung
`0x0075` / `0xA013`):
SSC 229 кбит/с (256/328 «задыхаются»), SSC UHQ не поддерживается (наушники его не объявляют).
Для них «Авто» = 229, битрейты выше видны только с «Настройки ▸ Все битрейты»; SSC UHQ выбрать
можно, но список битрейтов пуст и поток не идёт, пока «Все битрейты» не включены. Наушникам без профиля всегда показываются все битрейты.
* SSC UHQ — захват 48 кГц апсемплится ×2 до 96 кГц, кадр 9 мс. Samsung Galaxy Buds2 Pro принимают его, хотя
  не объявляют.
* Битрейты, чьи кадры не влезают в пакет наушников (AAC 256, SSC 328, UHQ 886), появляются в
  списке только с «Макс. MTU». Байт конфигурации SSC (`ctl ssccap`) не сохраняется — только до
  перезапуска трея.

### Кнопки и громкость

* Касания наушников → медиаклавиши Windows: одно — пауза/воспроизведение, двойное — следующий
  трек, тройное — начало / предыдущий трек (как решит плеер). Наушникам сообщается, играет ли
  что-то, чтобы касание отправляло нужную команду.
* Громкость Windows ⇄ громкость наушников (AVRCP), в обе стороны.
* **Mute** в Windows (клавиша, микшер) глушит поток в наушники.
* При потере связи (наушники в кейсе) программа ставит воспроизведение на паузу и
  возвращает звук динамикам до возвращения наушников.

## Как это устроено

Один файл `ssc.exe`, несколько ролей:

```
ssc.exe            трей (пользователь)  ── stdin/stdout JSON ──►  ssc.exe engine (пользователь)
   │                                                               MT79xx прошивка (WinUSB)
   │ \\.\pipe\SSCv2Helper (доступ: SYSTEM, админы, владелец)       BTstack: A2DP/AVDTP/AVRCP, LE HID
   ▼                                                               WASAPI → AAC (FDK) / SSC (libssc) → RTP
ssc.exe service (LocalSystem)                                      громкость ⇄ AVRCP, кнопки, мышь
   переключение драйвера, ключи из реестра, VB-CABLE
```

* **Движок — отдельный процесс** на каждый сеанс: свежее состояние BTstack, падение C-кода не
  роняет трей; трей перезапускает движок и откатывает изменения звука.
* **Служба** нужна только для привилегированного: смена драйвера (временный сертификат на
  каждое переключение), чтение `BTHPORT\Parameters\Keys` (доступно только SYSTEM), запись
  нового ключа обратно в Windows, установка VB-CABLE. Без службы те же операции выполняет
  копия `ssc.exe` с запросом UAC. Служба запускается из `Program Files\SSCv2`.
* **Ключи.** Наушники и мышь сопрягаются в Windows, затем «Импорт сопряжённых в Windows»
  переносит ключи — тот же адрес контроллера, повторное сопряжение не нужно и связь с
  Windows не ломается. Если наушники сопрячь при включённом кодеке, новый ключ при запущенной
  службе записывается и в реестр Windows.
* **Виртуальные наушники.** Драйвер VB-CABLE (VB-Audio, подписан Microsoft) встроен в
  `ssc.exe` (`internal/vbcable/files`). При включении кодека программа сама ставит устройство
  и называет его по выбранным наушникам; оно становится выводом по умолчанию, его ползунок
  управляет наушниками. Удаляется вместе со службой или программой.

### Почему драйвер меняется «на месте»

Адаптер переключается так: отключить устройство → поставить/удалить пакет WinUSB → включить
(`pnputil /disable-device`, `/add-driver /install` или `/delete-driver /uninstall`,
`/enable-device`). Удалять узел (`/remove-device /subtree`) нельзя: вместе с ним удаляются
записи реестра Bluetooth, и после каждого возврата Windows видела наушники как *новое*
устройство (громкость 100 %, скачки звука, «призраки» в диспетчере устройств). Старый способ
остался запасным: он включается сам, если Windows не дала остановить адаптер.

### Go и C

Всё своё — на Go: драйвер (SetupAPI), загрузчик прошивки MT79xx (WinUSB), WASAPI/громкость/
IPolicyConfig (COM напрямую), логика BT (события, A2DP, AVRCP, мост мыши), служба, трей,
установка. Сторонние библиотеки на C/C++ собираются через cgo прямо `go build` (без CMake):
**BTstack** (`third_party/btstack`), **FDK-AAC** (`third_party/fdk-aac`) и наш **libssc**
(`libssc/src`). `tools/genwrap` генерирует по файлу-обёртке на исходник
(`internal/bt/zbt_*.c`, `internal/codec/aac/zfdk_*.cpp`, `internal/codec/ssc/zssc_*.c`).

| Пакет | Назначение |
|---|---|
| `cmd/ssc` | точка входа, роли процесса, иконка |
| `internal/app` | трей: меню, кодеки, установка/удаление, команды `ctl` |
| `internal/engine` | процесс потока: захват → кодек → BT, переподключение, кнопки, mute |
| `internal/bt` | BTstack: запуск, A2DP-источник (AAC/SSC), AVRCP, поиск, мост BLE-мыши |
| `internal/codec/aac`, `internal/codec/ssc` | AAC-LC (LATM как у Android), SSC через libssc |
| `internal/audio` | WASAPI-захват, громкость и mute, виртуальные наушники |
| `internal/driver`, `internal/mtk` | WinUSB ↔ BTHUSB, RAM-прошивка MT79xx (из DriverStore `mtkbt*`) |
| `internal/helper` | служба, канал, привилегированные операции, UAC |
| `internal/install` | Program Files, ярлык, удаление |
| `internal/keys`, `internal/vbcable` | ключи (keys.json, реестр Windows), встроенный драйвер VB-CABLE |
| `internal/i18n`, `internal/config`, `internal/logx`, `internal/tray` | языки, настройки, журналы, значок |
| `libssc/` | своя реализация SSC: [README](libssc/README.ru.md), [план](libssc/PLAN.ru.md) |

## Сборка

Нужны Go 1.24+ и MinGW-w64 (gcc/g++) в `PATH`.

```bat
build.cmd
```

Результат — `bin\ssc.exe` с версией `0.1 #<хеш>` из git. Первая сборка компилирует BTstack,
FDK-AAC и libssc (~1–2 мин), дальше кеш. Для переключения в WinUSB нужен Windows 10+ SDK
(`makecat.exe`, `signtool.exe`).

```bat
go test ./...
```

## Файлы

* `%APPDATA%\SSCv2\settings.json` — кодек, битрейты, язык, «Макс. MTU», наушники/мышь, debug.
  Каждое чтение и сохранение пишется в `tray.log` (кто сохранил).
* `%APPDATA%\SSCv2\keys.json` — ключи сопряжения (секреты, только для этого пользователя).
* `%LOCALAPPDATA%\SSCv2\logs\` — `tray.log`, `engine.log`, `engine-c.log`, `helper.log`,
  `debug.log`; журнал службы — `%ProgramData%\SSCv2\service.log`.

## Командная строка

```bat
ssc.exe status
ssc.exe ctl status | info | version | log [debug|tray|engine|helper] [N]
ssc.exe ctl mode off|aac|ssc|ssc_uhq | bitrate auto|<кбит/с> | maxmtu on|off | lang ru|en
ssc.exe ctl debug on|off | import windows | service install|remove | scan | connect <адрес>
ssc.exe ctl quit | uninstall
```

Диагностика: `ctl aac frag` (кадры AAC 256 по двум пакетам RFC 3016 — Samsung Galaxy Buds2 Pro их не
собирают), `ctl ssccap auto|<hex>` (байт конфигурации SSC), `SSCV2_SSC_SHIFT=1..8`
(подать SSC вход с запасом бит).

### Отладочный журнал

Включается в «Настройках», командой `ssc.exe ctl debug on` или переменной `SSCV2_DEBUG=1`.
Трей, движок и служба пишут в один файл `%LOCALAPPDATA%\SSCv2\logs\debug.log` по времени; у
строки есть категория (`findstr " vol:" debug.log`):

| Категория | Что пишется |
|---|---|
| `mode`, `ui`, `helper` | переключения, пункты меню, запросы к службе и журнал скрипта смены драйвера |
| `dev`, `vol` | события аудиоустройств и каждое изменение громкости/mute — с источником |
| `hci`, `l2cap`, `sdp` | HCI-команды и события, L2CAP-каналы |
| `avdtp`, `avrcp` | A2DP-сигнализация, AVRCP (громкость, кнопки наушников) |
| `att`, `smp` | BLE-мышь: GATT и сопряжение |
| `media` | раз в 5 с — сводка аудиопакетов, отчётов мыши и рекламы |

Ключи сопряжения (link key, LTK) в журнале маскируются. Файл ротируется при 64 МБ.

## Лицензии

BTstack — лицензия BlueKitchen (только некоммерческое использование), FDK-AAC — лицензия
Fraunhofer, Opus (в libssc) — BSD; тексты в `third_party/*` и `libssc/src/opus/COPYING`.
VB-CABLE — donationware от VB-Audio: для личного использования бесплатно, распространение в
составе другой программы — только с их разрешения. libssc и SSC — только для личного
использования.
